Generated by `python -m firmable profiles` over 50 profiles, as of 2026-11-06.

**If a source is deleted.** Almost every linked entity spans exactly two sources, so deleting either one mostly removes the link and the profile with it. The first number below is therefore close to "how many profiles used this source". The columns after it measure the damage to the values.

**If a source is wrong but still present.** Deleting it is the easy case. The harder one is a source that stays and is wrong. How much a wrong source can do depends on what it claims:

- *A wrong value on a contested field* shows up: it loses or wins on support, and the losing value and the reason are in the profile. Reliability scores are the agent's opinion, not measured, so a wrong source rated highly can still win.
- *A wrong value nobody else states* is invisible. Each profile field records its sources, and the count below is how many fields rest on one source alone, with no other source to contradict it.
- *A wrong identifier* is the most damaging, because an exact ABN match links at high confidence. A checksum cannot catch a valid ABN on the wrong row. The ACT invoices show this is real (see `outputs/audit/config_audit.md`). A link refusal only triggers when names also disagree, so a wrong ABN beside a matching name would still merge.
